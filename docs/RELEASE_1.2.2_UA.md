# Deep Bounce 1.2.2 — що змінено і що зробити вручну

Версія 1.2.2, versionCode 9, пакет `com.deepbounce.game`, target SDK 36, той самий ключ завантаження.
Гілка розробки: `release/1.2.2`. Формат збереження не змінювався (формат 4): оновлення поверх 1.2.1 зберігає
прогрес, покупки й налаштування.

## 1. Попередження Android 16 у Play Console

### «Використання застарілих edge-to-edge API або параметрів»
**Причина.** Шаблонна активність Godot 4.5.1 (`GodotApp.java`) під час кожного повернення в гру й після старту
рушія примусово викликала `Godot.enableImmersiveMode(..., true)` і `enableEdgeToEdge(..., true)` →
`WindowCompat.setDecorFitsSystemWindows` → `Window#setDecorFitsSystemWindows`, а під час запуску ще й
`androidx.activity.EdgeToEdge.enable()`, що задає застарілі кольори панелей (`setStatusBarColor`,
`setNavigationBarColor`). Android 15 позначив ці методи як застарілі й вимкнені.

**Що зроблено.**
- Власна активність `tools/android/template/GodotApp.java` (скрипт збірки кладе її замість шаблонної):
  без `EdgeToEdge.enable()` і без `enableImmersiveMode/enableEdgeToEdge`; системні панелі ховаються лише через
  незастарілий `WindowInsetsControllerCompat.hide(systemBars())` (свайп від краю показує їх тимчасово) — під час
  запуску, повернення в гру й отримання фокусу. Android 15+ сам малює застосунок від краю до краю.
- В експорті вимкнено вбудований immersive-режим Godot (`screen/immersive_mode=false`, `screen/edge_to_edge=false`).
- Плагін гри `DeepBouncePlay` повідомляє реальні відступи (видимі системні панелі + виріз камери), і
  `scripts/main.gd` розміщує поле та всі кнопки всередині безпечної зони; відступи перечитуються при поверненні з
  реклами/Google Play і раз на секунду (панелі можуть з'явитися без зміни розміру вікна).
- Знайдено на емуляторі: у першій збірці 1.2.2 шаблонна активність знову показувала панелі одразу після того, як
  плагін їх ховав, — саме так виявилась справжня причина.

**Що може лишитися у звіті Play.** Самі бібліотеки Google та AndroidX усе ще *містять* такі виклики для старих
версій Android (перевірено навіть найновіші: `androidx.core` 1.19.1, `androidx.activity` 1.13.0,
`core-splashscreen` 1.2.0; також внутрішній код Google Mobile Ads і бібліотеки Godot — `Godot.enableImmersiveMode`,
який тепер ніхто не викликає). Гра цих шляхів не запускає, але Play аналізує код
статично і може й далі показувати ці місця з позначкою відповідних бібліотек. Це рекомендація, а не блокування
публікації; повністю зникне після оновлень цих бібліотек і рушія Godot. Google Mobile Ads 25.x вимагає новішого
Kotlin, ніж шаблон збірки Godot 4.5.1, тому SDK лишився 24.9.0.

### «Обмеження зміни розміру й орієнтації на великих екранах»
**Причина.** У маніфесті було `android:screenOrientation="portrait"`.

**Що зроблено.**
- Маніфест більше не фіксує орієнтацію (Godot: `window/handheld/orientation=6` → `fullUser`), активність
  `resizeableActivity=true`.
- Під час запуску гра визначає розмір екрана за правилом Android (найменша сторона ≥ 600 dp): на **телефонах**
  просить портрет (`SCREEN_SENSOR_PORTRAIT`), на **планшетах, розкладених складаних і у вікнах** дозволяє будь-яку
  орієнтацію й зміну розміру.
- Розкладка вже масштабувала поле 9:16 у будь-яке вікно; тепер у широких вікнах по боках видно стіни шахти
  (раніше фон обривався), затемнення модальних вікон покриває весь екран. Фізика не змінювалась — вона працює в
  координатах поля, незалежних від розміру вікна.
- Перевірено рендером: 1080×2400 (телефон 20:9), 1600×2560 (планшет, портрет), 2560×1600 (планшет, альбом),
  2208×1840 (розкладений складаний), 1280×800 (мале альбомне вікно) — меню, рівень, магазин, друга спроба.

## 2. AdMob — перехід на справжню рекламу (коли буде готово)
Поточна збірка: `use_test_ads=true`, офіційні тестові блоки Google (для Closed Alpha це правильно).

Коли акаунт AdMob готовий (застосунок прив'язаний, 3 блоки створені, повідомлення GDPR опубліковано):
1. AdMob → Apps → Deep Bounce → App settings → **App ID** (`ca-app-pub-…~…`).
2. AdMob → Ad units → створити **Rewarded** «Continue», **Rewarded** «Double crystals», **Interstitial** «Between runs».
3. У `config/monetization.cfg`:
   ```ini
   [admob]
   use_test_ads=false
   real_app_id="ca-app-pub-…~…"
   real_rewarded_revive="ca-app-pub-…/…"
   real_rewarded_double="ca-app-pub-…/…"
   real_interstitial="ca-app-pub-…/…"
   ```
4. `tools/android/check_store_ready.sh` має сказати READY; лише тоді production-збірка.
Тестовий режим не вимикається, поки поля `real_*` порожні: гра й плагін експорту беруть тестові ID.

## 3. app-ads.txt — правильне розміщення
AdMob шукає файл **у корені домену**, вказаного як «Веб-сайт» розробника в Google Play:
`https://<домен>/app-ads.txt` (не в підпапці). Сторінка `https://vladislavdrucok-tech.github.io/deepbounce/` —
це підпапка, тому для GitHub Pages потрібен окремий репозиторій користувача:
1. Створи **публічний** репозиторій з назвою рівно `vladislavdrucok-tech.github.io`.
2. Поклади в корінь файл `app-ads.txt` з одним рядком (pub-ID з AdMob → Settings → Account information):
   ```
   google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0
   ```
   і (необов'язково) `index.html` з посиланнями на політику й умови.
3. Settings → Pages → Deploy from a branch → `main` / root. Перевір `https://vladislavdrucok-tech.github.io/app-ads.txt`.
4. Play Console → Присутність у магазині → Налаштування магазину → **Веб-сайт**: `https://vladislavdrucok-tech.github.io`
5. AdMob → Apps → Deep Bounce → app-ads.txt → перевірка (до 24 год).
Шаблон: `site/app-ads.txt.template`. Скажи, коли репозиторій створено, — я підготую файли.

## 4. Google Play Billing — дії в Play Console
Товари створюються лише після того, як у Play Console є завантажена збірка з Billing (уже є — 1.2.1).
1. **Монетизація → Товари → Разові продукти → Створити**, для кожного ID точно як нижче:

   | ID | Тип у грі | Ціна (USD, база) |
   |---|---|---|
   | `db_no_ads` | постійний (acknowledge) | 3.99 |
   | `db_ball_amber` | постійний | 0.99 |
   | `db_ball_frost` | постійний | 1.99 |
   | `db_ball_obsidian` | постійний | 1.99 |
   | `db_cannon_bronze` | постійний | 1.99 |
   | `db_cannon_crystal` | постійний | 2.99 |
   | `db_cannon_obsidian` | постійний | 2.99 |
   | `db_support_small` | витратний (consume) | 0.99 |
   | `db_support_medium` | витратний | 2.99 |
   | `db_support_large` | витратний | 4.99 |
   | `db_support_extra` | витратний | 9.99 |

2. Для кожного: назва й опис англійською + переклади з `docs/PLAY_PRODUCTS.md`; варіант покупки «Купити»;
   ціна в USD → «Установити ціни» (Google перерахує валюти); **Активувати**. Окремого прапорця «витратний» у
   Play Console немає — споживання робить код гри.
3. **Ключ ліцензування:** Монетизація → Налаштування монетизації → Ліцензування → скопіювати Base64-ключ і надіслати
   мені (він публічний) — впишу в `[billing] license_key`, після чого підписи покупок перевірятимуться на пристрої.
4. **Тестування ліцензій:** Налаштування (акаунта розробника) → Тестування ліцензій → додати Gmail тестувальників.
   Вони платять тестовими картками (зокрема «повільна» — для перевірки очікуваних покупок).
5. Повернення коштів для перевірки: Керування замовленнями → замовлення → Повернути кошти + **Відкликати право**.

Паролі, ключ підпису та інші секрети в GitHub не зберігаються.
