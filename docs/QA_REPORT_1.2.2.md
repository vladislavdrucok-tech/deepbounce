# Deep Bounce 1.2.2 — фінальний QA-звіт

Версія 1.2.2, versionCode 9, пакет `com.deepbounce.game`, target SDK 36, min SDK 24, Godot 4.5.1.
Гілка `release/1.2.2`. Позначки: **PASS** — перевірено й працює; **FAIL** — перевірено й не працює;
**NOT TESTED** — перевірка не проводилась (причина вказана). Непроведені перевірки PASS не позначаються.

## 3. Android (емулятор Android 11 / API 30, x86_64, без апаратного прискорення)

Емулятор Google APIs, Android 11, 1080×2280 @440 dpi, 4 ГБ RAM, програмний GPU (swangle). Великі екрани імітовано
зміною дисплея (`wm size` / `wm density` / `user_rotation`) — це реальна поведінка Android 11 з такими параметрами,
але не заміна справжнього планшета чи складаного пристрою. Повний сценарій нижче пройдено на збірці
`e46a713a…dc717`; фінальна збірка `fe931a36…ad9b` відрізняється лише розміром фону для широких екранів і пройшла
окремий димовий тест: оновлення 1.2.1 → 1.2.2 (збереження не змінилось, SHA-256 встановленого APK збігається з
фінальним), запуск, телефон (портрет, панелі приховані), планшет → поворот в альбом 2560×1600, назад у телефон — **PASS**.

| Перевірка | Результат |
|---|---|
| Оновлення 1.2.1 (versionCode 8) → 1.2.2 (9) через `pm install -r`: файл збереження не змінився (md5), гра стартує з формату 4, кристали, незавершений забіг «Нескінченний», налаштування на місці | **PASS** |
| Телефон 1080×2280 (392 dp): портрет (`USER_PORTRAIT`), статус- і навігаційна панелі приховані (`mVisible=false`), меню й гра в безпечній зоні | **PASS** |
| Планшет 1600×2560 @320 (800 dp), портрет: гра знімає обмеження орієнтації (`FULL_USER`), панелі приховані | **PASS** (після 2 виправлень, див. нижче) |
| Планшет, альбом 2560×1600: дисплей повертається, поле 9:16 по центру зі стінами шахти, кнопки не обрізані | **PASS** |
| Розкладений складаний 2160×1840 (920 dp) → будь-яка орієнтація; складений 1080×2280 → знову портрет | **PASS** |
| Мале вікно 720×1280 @320 (360 dp): портрет, нічого не обрізано | **PASS** |
| Згортання (Home) і повернення: стан збережено, панелі знову приховані | **PASS** |
| `kill -9` під час залпу (імітація аварійного завершення): файл збереження цілий (валідний JSON), після запуску «Продовжити · Нескінченний 16 м», кристали ті самі, нічого не подвоїлось | **PASS** |
| Тривала гра у двох сесіях: 6 + 30 спроб залпу свайпом (глибина 12 → 16 → 20 м, кристали 55 → 62 → 74), екран вибору посилень, екран «Без реклами» | **PASS** |
| Пам'ять (PSS): 241.7 МБ після запуску → 243.0 → 250.2 → 254.6 → 254.8 МБ (старт, продовження забігу, далі кожні 10 спроб залпу) — виходить на плато, витоку не видно | **PASS** (емулятор) |
| Без мережі/без Google Play: Billing «недоступно», екран покупки показує «Недоступно / Повторити», UMP повертає помилку → реклама не запитується, гра не зависає | **PASS** |
| FPS на емуляторі | **NOT TESTED** (програмний GPU емулятора не показовий) |

**Що знайдено на емуляторі й виправлено:**
1. Перша збірка 1.2.2 не ховала панелі — шаблонна активність Godot знову показувала їх (і викликала застарілий
   `setDecorFitsSystemWindows`) → власна активність.
2. Планшет вважався телефоном: Godot на Android віддає DPI на момент запуску → тепер рішення бере Android
   `smallestScreenWidthDp` через плагін.
3. Android повідомляв нову найменшу ширину вже після події зміни розміру → додано повторну перевірку раз на секунду.
Усі три — з регресійними тестами (PLAY, Kotlin unit) і повторною перевіркою на емуляторі.

## 5. Продуктивність

- Фізика: 0.11–0.23 мс на тік (кадр при 60 FPS — 16.7 мс), найгірший тік < 1.3 мс.
- Кадр рендер+фізика, найдовший залп (32 кульки), **програмний** OpenGL (llvmpipe) на ПК без GPU, той самий тест і
  машина: 1.2.1 — 20.3 / 21.0 мс, 1.2.2 — 18.5–20.4 мс (середнє). **Регресії немає.** (Учорашні 13.8 мс — той самий
  код на менш завантаженому хості; абсолютні числа програмного рендера не відповідають телефону з GPU.)
- Під час перевірки помічено, що в 1.2.2 фон для широких екранів був фіксовано дуже широким — тепер він точно під
  видиму область (на телефоні — як в 1.2.1).
- Пам'ять на емуляторі (PSS): плато ~255 МБ після 30 спроб залпу, витоку не виявлено.
- Справжній FPS і нагрів на телефоні з GPU — **NOT TESTED** (немає пристрою).

## 6. Не перевірено (NOT TESTED) і чому

| Що | Причина |
|---|---|
| Android 13, 15, 16 | у середовищі немає KVM (емулятор лише в програмному режимі, API 30 завантажується ~15 хв) і лише ~6 ГБ диска; образи API 33/35/36 тут непрактичні |
| Справжній телефон, планшет, складаний пристрій | фізичних пристроїв немає (великі екрани перевірено рендером на ПК і зміною розміру дисплея емулятора) |
| Справжні покупки, PENDING, refund у Google Play | потрібні Play-збірка з треку тестування й акаунти тестувальників ліцензій |
| Показ реклами, форма згоди UMP, перевірка app-ads.txt | тестові ID лише в Play-збірці на пристрої з мережею; app-ads.txt ще не опубліковано |
| Play Games | не налаштовано в Play Console |
| Чи зникли попередження Play Console | видно лише після завантаження AAB у Play Console |
| Оновлення через сам Google Play | потрібне завантаження в трек тестування |
